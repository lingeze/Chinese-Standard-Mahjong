# 145 维特征扩展方案

## 论文依据

来自课程 PDF（Slide 6），IJCAI 2020 第4名（中科大，纯监督学习）：

> 145通道 = 自己手牌4 + 每个人(吃4+碰1+杠1)×4 + 自己暗杠1 + 每个人弃牌历史28×4 + 剩余牌4

验证：4 + 24 + 1 + 112 + 4 = 145 ✓

---

## 145 通道详细布局

```
Ch 0-3:   自己手牌 (4通道)
          编码方式：每张牌出现1次→ch0=1，出现2次→ch1=1，出现3次→ch2=1，出现4次→ch3=1
          与当前 HAND 通道 (ch2-5) 完全相同

Ch 4-27:  四人副露 (24通道 = 6×4人)
          每个玩家 6 通道：
            - 吃 4ch: slot-based，每人最多4组吃。每通道标记一组吃的三张牌（左中右）
            - 碰 1ch: 标记碰过的牌位置（multi-hot）
            - 杠 1ch: 标记明杠过的牌位置（来自别家弃牌的杠，不含暗杠）

          玩家0(自己): ch 4-9
          玩家1(下家): ch 10-15
          玩家2(对家): ch 16-21
          玩家3(上家): ch 22-27

Ch 28:    自己暗杠 (1通道)
          标记自己暗杠的牌位置。别人暗杠无法看到牌面（存为 CONCEALED），不在此通道标记

Ch 29-140: 四人弃牌历史 (112通道 = 28×4人)
          每玩家 28 通道 = 万1-9(9) + 条1-9(9) + 饼1-9(9) + 字牌合并(1)
          每通道标记该玩家是否弃过对应类型的牌（累积标记，非时序）

          玩家0: ch 29-56
          玩家1: ch 57-84
          玩家2: ch 85-112
          玩家3: ch 113-140

Ch 141-144: 剩余牌墙 (4通道)
          每人剩余可摸牌数 / 21，均匀填充整个 4×9 网格
```

**注意**：论文方案中没有显式的门风/圈风通道。风位信息通过手牌分布、副露历史等间接体现，这是 IJCAI 第4名团队的实际做法。

## 各文件详细修改

### 1. RL/feature.py（实际被 battle.py 使用的文件）

#### 1.1 常量定义

```python
# 改前
OBS_SIZE = 6

OFFSET_OBS = {
    'SEAT_WIND': 0,
    'PREVALENT_WIND': 1,
    'HAND': 2
}

# 改后
OBS_SIZE = 145

OFFSET_OBS = {
    'HAND': 0,             # 0-3:   手牌计数 (4ch)
    'MELD': 4,             # 4-27:  四人副露 (24ch)
    'CONCEALED_KONG': 28,  # 28:    自己暗杠 (1ch)
    'DISCARD': 29,         # 29-140: 四人弃牌历史 (112ch)
    'WALL': 141,           # 141-144: 剩余牌墙 (4ch)
}
```

#### 1.2 `__init__` 初始化

```python
# 改前
self.obs = np.zeros((self.OBS_SIZE, 36))
self.obs[self.OFFSET_OBS['SEAT_WIND']][self.OFFSET_TILE['F%d' % (self.seatWind + 1)]] = 1

# 改后
self.obs = np.zeros((self.OBS_SIZE, 36))
# 初始化牌墙通道为 1.0（游戏开始时每人 21 张）
self.obs[self.OFFSET_OBS['WALL']:, :] = 1.0
```

#### 1.3 新增辅助方法

```python
def _obs_update(self):
    """统一更新全部通道：手牌 + 副露 + 弃牌 + 牌墙"""
    # 1. 手牌计数 (ch 0-3) — 原有逻辑
    self.obs[self.OFFSET_OBS['HAND']:self.OFFSET_OBS['HAND']+4, :] = 0
    d = defaultdict(int)
    for tile in self.hand:
        d[tile] += 1
    for tile in d:
        self.obs[self.OFFSET_OBS['HAND']:self.OFFSET_OBS['HAND']+d[tile],
                 self.OFFSET_TILE[tile]] = 1

    # 2. 副露 (ch 4-27)
    self._meld_update()

    # 3. 弃牌历史 (ch 29-140)
    self._discard_update()

    # 4. 牌墙 (ch 141-144) — 在 Draw 事件中单独更新
```

```python
def _meld_update(self):
    """将 self.packs 编码到 MELD + CONCEALED_KONG 通道"""
    self.obs[self.OFFSET_OBS['MELD']:self.OFFSET_OBS['WALL'], :] = 0

    for p in range(4):
        base = self.OFFSET_OBS['MELD'] + p * 6
        chi_slot = 0  # 当前吃到第几组（最多4组）
        for packType, tile, offer in self.packs[p]:
            tid = self.OFFSET_TILE.get(tile)
            if tid is None:
                continue  # 跳过 CONCEALED（别人的暗杠看不到牌）

            if packType == 'CHI':
                # 每组吃占用一个 chi 通道（标记三张牌）
                if chi_slot < 4:
                    self.obs[base + chi_slot, tid] = 1
                    # 左右牌
                    num = int(tile[1])
                    color = tile[0]
                    if num > 1:
                        lt = self.OFFSET_TILE.get(color + str(num - 1))
                        if lt is not None:
                            self.obs[base + chi_slot, lt] = 1
                    if num < 9:
                        rt = self.OFFSET_TILE.get(color + str(num + 1))
                        if rt is not None:
                            self.obs[base + chi_slot, rt] = 1
                    chi_slot += 1
            elif packType == 'PENG':
                self.obs[base + 4, tid] = 1  # 碰通道
            elif packType == 'GANG':
                if offer == 0 and p == 0:
                    # 自己的暗杠 → CONCEALED_KONG 通道
                    self.obs[self.OFFSET_OBS['CONCEALED_KONG'], tid] = 1
                # 所有杠也标记在杠通道
                self.obs[base + 5, tid] = 1
```

```python
def _discard_update(self):
    """将 self.history 编码到 DISCARD 通道"""
    for p in range(4):
        base = self.OFFSET_OBS['DISCARD'] + p * 28
        for tile in self.history[p]:
            self._set_discard_channel(base, tile)

def _set_discard_channel(self, base, tile):
    """将一张弃牌映射到 28 通道中的对应位置"""
    color = tile[0]
    num = int(tile[1])
    if color == 'W':
        idx = base + (num - 1)
    elif color == 'T':
        idx = base + 9 + (num - 1)
    elif color == 'B':
        idx = base + 18 + (num - 1)
    else:  # F / J → 字牌合并到最后一个通道
        idx = base + 27
    self.obs[idx, self.OFFSET_TILE[tile]] = 1
```

#### 1.4 `request2obs` 事件处理修改

在以下事件中追加新通道更新：

- **Wind**: 不再设置 PREVALENT_WIND 通道
- **Deal**: `_hand_embedding_update()` → `_obs_update()`
- **Draw (p==0)**: 追加 `self.obs[self.OFFSET_OBS['WALL'] + p, :, :] = self.tileWall[p] / 21`
- **Draw (p!=0)**: 追加 wall 更新
- **Play (p==0)**: 追加 `_discard_update()` (手牌出牌后更新弃牌历史)
- **Chi/Peng/Gang/AnGang/BuGang (p==0)**: 追加 `_meld_update()`

## 关于新旧模型对弈的问题

### 核心约束

battle.py 使用**同一个 FeatureAgent 类**为所有4个座位生成 observation。如果 FeatureAgent.OBS_SIZE = 145，则所有模型都必须接受 `(B, 145, 4, 9)` 的输入。**旧的 6 通道 checkpoint 无法直接加载到 145 通道模型中**（tensor shape 不匹配）。

这意味着：

> **145 维 ResNet/CNN 不能直接与旧的 6 维 ResNet/CNN 对弈。**

### 解决方案：让 battle.py 支持多种 OBS_SIZE 混战

修改思路：允许每个座位使用不同的 FeatureAgent 子类。

#### 改动点

**① feature.py**：新增 `FeatureAgent145` 子类

```python
class FeatureAgent145(FeatureAgent):
    OBS_SIZE = 145
    OFFSET_OBS = { ... }  # 145 通道布局
```

保留原有 `FeatureAgent`（OBS_SIZE=6）不动。两个类共存，action space 相同（235），接口一致。

**② env.py**：支持 per-seat agent_clz

将 `MahjongGBEnv.__init__` 中的：
```python
self.agentclz = config['agent_clz']  # 单一类型
```
改为支持：
```python
self.agent_clzs = config.get('agent_clzs', [config['agent_clz']] * 4)  # 4座各一
```

**③ battle.py**：为每个模型关联其 FeatureAgent 类

```python
# 用法示例：145维 ResNet vs 6维 CNN
python battle.py \
    --models log/resnet145/19.pkl log/cnn6/19.pkl \
    --model-classes model.ResNetModel model.CNNModel \
    --feature-classes feature.FeatureAgent145 feature.FeatureAgent \
    --games 500
```

ModelWrapper 记录自己对应的 FeatureAgent 类，env 创建 agent 时按座位选择对应的类。

### 推荐方案

**短平快做法**：把旧模型也用 145 维重新训练一遍，在同维度下公平对比。

具体步骤：
1. 修改 feature.py → 145 维
2. 运行 `python preprocess.py` 重新生成 145 维数据
3. 分别训练 145 维的 CNN 和 145 维的 ResNet
4. 用 battle.py 对比两个 145 维模型

如果想保留旧 6 维模型用于对比，再按上述方案改造 battle.py 支持混战。

## 训练流程

```
1. 修改 RL/feature.py + Sl/feature.py → OBS_SIZE = 145
2. 修改 Sl/model.py → CNNModel(in_channels=145)
3. 运行 preprocess.py → 生成新的 data/*.npz (145×4×9)
4. 运行 supervised.py → 训练 ResNetModel(in_channels=145)
5. 运行 battle.py → 对战评估
```

**注意**：145 维数据每个样本约 5.5KB（原来 ~450B），磁盘占用增加约 12 倍。如果数据量很大（如 98000 局），可能需要实现数据延迟加载（dataset.py 逐文件加载而非全部缓存到内存）。
